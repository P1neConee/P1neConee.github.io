腾讯WorkBuddy广州沙龙纪要

忽然发现都忘光光了，只能丢给ai整理了，下次遇到会议应当录音

整理自现场幻灯片（16 张）+ 沙龙总结草稿。主办方：腾讯云开发者社区 / 腾讯云开发者星盟 / WorkBuddy 客户成功团队。
一条主线（碎片化 → 链闭环）：传统 AI coding 面临「碎片化、交付链不闭环」；本场用 Vibe → Spec → Harness / Skill / 自动化 把「个人能跑」升级为「企业可复现」。
全篇配图均来自现场幻灯片，按章节对应插入。

01 基本概念

Vibe Coding

  • 优势：把意图快速变成可运行结果；适合低风险探索、原型验证、个人工具。
  • 流程：Prompt(意图) → Run(运行) → Observe(观察) → Iterate(调整)。
  • 局限：企业生产仍需补齐约束。

探索模式 vs 企业交付模式

中间靠 Spec + Harness 衔接。

维度 探索模式 企业交付模式
目标 找可行方向 稳定完成任务
控制 人工全程在场 策略与审批内建
证据 演示结果 验收 / Trace / 审计
容错 随时重做 断点 / 回滚 / 恢复

Spec


把「我想要」变成可测试的契约（= 验收协议，不是 prompt）。四块：

  • WHY：业务目标 / 用户与价值
  • WHAT：行为与数据 / 非功能要求
  • DONE：验收标准 / 测试与证据
  • BOUNDARY：权限边界 / 回滚与例外

Harness（执行系统）

围绕大模型，LLM 决策 → MCP → 工具链运行。模型 + Harness = Agent；生产级要解决「可持续、可受控、可审计」的工程问题。

Agent

识别任务 / 需求 → 分拆任务链 → 自主调工具；面向「整个任务」而非单次对话。

  • Chat：一次问答 = 目标完成
  • Agent：面向整个任务

工具面举例：操控浏览器、抢票等；人负责「原型修正」；规模化靠多 Agent 协同。

02 上下文与记忆

三层记忆（各管一件事）

  • 云端 Profile：只读长期画像（职业、习惯、近期关注）
  • 用户级 MEMORY.md：写「记住」时落盘，跨项目硬规则（约 4000 字上限）
  • 空间当日日志：系统写，记录各空间发生了什么
  • 三层都管不到的 = 项目级经验（工作流底盘）

何时开新会话 —— 四个信号

  1. 开头定的规矩开始被忘（如「别动表头」又动了）
  2. 话题已换（旧上下文全是噪音）
  3. 同一段改了几轮越改越差（陷进局部最优）
  4. 反复重申同一要求（基本没救了）

→ 别喊「重做」（会毁掉已改对的部分）；要么指明位置局部改，要么带结论开新局。开新局前让它写 handoff.md（已定结论 / 待办 / 坑），新会话首句「先读 handoff.md」。

四条纪律（每条对应一次翻车）

  1. 改文件前先备份：文件名加日期，让它「复制一份再改」
  2. 改写 / 复盘 / 分析先上传素材：别让它凭空编
  3. 长对话定期自我摘要：每完成一大步发「用两三句话总结进展和待办，钉在这里」，成为高权重参考点
  4. 关键决策用 @ 钉住上下文：比反复强调管用得多

plan 模式


输入框左下角【计划】先出方案 → 确认再动手；提示词优化在右下角 ◇。

03 Skill

触发率 = 四道漏斗关卡

  1. 被触发：description 写清「什么场景用」
  2. 读得对：步骤写死先读哪些文件、什么顺序
  3. 做得稳：模板 + 禁做事项 + 自检清单，输出格式不漂移
  4. 可迭代：失败案例入库，每次改动回归验证

每过一关数量衰减 —— 写 Skill 就是修这个漏斗。

最快写法 = 拆别人的

  • 路子一：灵感频道「一键做同款」（复制提示词 → 只改目标 / 输入 / 约束 → 跑通验证）
  • 路子二：GitHub 开源 workbuddy-skills / WorkBuddy-Starter / 实战蓝皮书(WorkBuddyGuide) 的 SKILL.md 是完整工程范本。拆 3 个别人比闭门写 10 个学得快。

工程化四步

  1. 多用好 Skill、拆着用（看它每步在干什么）
  2. 拿一个小的真实需求练手（让 AI 先深度拆解学习那几个 Skill）
  3. 做好后自己天天用（一次性任务随口说，天天重复才值得固化成 Skill）
  4. 让 AI 按一周交流列出该做成 Skill 的场景

容易漏的两样

  • 输出格式规范：锁死 HTML 骨架 / 行动清单 [角色][时限]动作→产出 / 邮件段落，换模型产出一致
  • 模块路由 = 渐进式披露：SKILL.md 只当入口，细则 / 模板 / 数据基线分文件，用到才给，上下文不被细则挤爆

要点：skill description 是给 AI 的触发点，不是「它是什么」；prompt 是任务，skill 是做法。

04 自动化与专家团

同一任务，Ask / Plan / Craft 发三句不同的话


真实案例：把团队这季度 40 份客户反馈整理成问题分布报告。

  • Ask：只盘现场，一份文件都不动
  • Plan：先看它打算怎么干再批（看到「覆盖原文件」直接打回）
  • Craft：直奔成品，默认读材料、写文件（前两步盘清才放权）

常见乱用：什么任务都直接进 Craft —— 它默认心态是「完成任务」，不是「陪你确认边界」。

已跑起来的自动化

  1. 每日 10:00 企业风险监控日报（采集 → 生成 HTML → 自检通过才发邮件，提示词开箱即用）
  2. AI 工具箱（按部门岗位定制，一人一套：市场 / 法务 / 运营各拿各的）
  3. Skill 流（公司内部沉淀报告生成 / 文档规范化 / 会议纪要）
  4. 每周自进化（风险监控系统自己长规则，周一回顾把重复问题固化成新规则）

→ 横向规律：机械化苦工交给 AI，人只保留判断与决策。

动手做 AI 应用前先想清 5 个问题（让 WorkBuddy 多反问你）

  1. 需求多久做一次？（频率低就别做应用，手工或现成工具更快）
  2. 怎么判定最后产品是否成功？（核心页面 / 仪表盘先定清楚）
  3. 每个关卡从哪来、玩法多久变一次？（决定模型调用 / 定时任务 / 刷新策略 / 成本）
  4. 什么算异常 / 不达标，阈值多少？（告警 / 降级 / 人工介入边界先定死）
  5. 结论给谁看、怎么送到手上？（决定交付形态）

附：开源经验沉淀

  • wa-gamexuqiu：模糊想法 → 能开工的需求（用户 / 核心流程 / 功能边界 / 验收标准）
  • askmore：通过 AI 反复追问，明确需求是否被接住
  • 写代码的 Skill：拿需求一个闭环一个闭环做出来（页面 / 云函数 / AI 对话能力）

主线一句话


Vibe → Spec → Harness（氛围感知 → 策略可执行透明）→ Coding Agent → Work Agent（能力从代码扩散到业务）→ Runtime → WorkBuddy（中台化场景与测度，明确落地）→ 洗牌 → 规模化（从工作流定位价值、建立战略）。
