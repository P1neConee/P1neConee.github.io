腾讯WorkBuddy广州沙龙纪要

本轮更新：基于 7 份官方演讲材料（PDF / PPTX）重写，覆盖全部出席嘉宾。此前版本仅来自现场幻灯片 + 速记草稿，现以演讲者原稿为准补全。
主办方：腾讯云开发者社区 / 腾讯云开发者星盟 / WorkBuddy 客户成功团队。沙龙时间：2026-10-25，广州站。
一条主线（碎片化 → 链闭环）：传统 AI coding 面临「碎片化、交付链不闭环」；本场用 Vibe → Spec → Harness / Skill / 自动化 把「个人能跑」升级为「企业可复现」。

一、主线框架：从 Vibe 到 Harness（卢建晖 / Kinfey Lo）

来源：卢建晖《从 Vibe 到 Harness：Agent Runtime 驱动的下一代企业工作流》（副标题：从 Coding Agent 到企业级 Work Runtime）。声明为原创技术内容。配图为现场幻灯片。

Vibe Coding

  • 优势：把意图快速变成可运行结果；适合低风险探索、原型验证、个人工具。
  • 流程：Prompt(意图) → Run(运行) → Observe(观察) → Iterate(调整)。
  • 局限：企业生产仍需补齐约束。

探索模式 vs 企业交付模式

中间靠 Spec + Harness 衔接。

维度 探索模式 企业交付模式
目标 找可行方向 稳定完成任务
控制 人工全程在场 策略与审批内建
证据 演示结果 验收 / Trace / 审计
容错 随时重做 断点 / 回滚 / 恢复

Spec


把「我想要」变成可测试的契约（= 验收协议，不是 prompt）。四块：

  • WHY：业务目标 / 用户与价值
  • WHAT：行为与数据 / 非功能要求
  • DONE：验收标准 / 测试与证据
  • BOUNDARY：权限边界 / 回滚与例外

Harness（执行系统）

围绕大模型，LLM 决策 → MCP → 工具链运行。模型 + Harness = Agent；生产级要解决「可持续、可受控、可审计」的工程问题。

Harness 七类工程问题（本次 PPTX 新增，标注了生产级必须补齐的能力域）：

  1. Agent Loop（执行循环）
  2. LLM Integration（模型集成）
  3. Tools & Actions（工具与动作）
  4. Memory & Context（记忆与上下文）
  5. Safety & Permissions（安全与权限）
  6. Orchestration（多 Agent 编排）
  7. Extensibility（Skills / Hooks / Plugins / MCP 扩展）

Agent 与 Coding Agent 的五次跃迁

识别任务 / 需求 → 分拆任务链 → 自主调工具；面向「整个任务」而非单次对话。Chat（一次问答=目标完成）vs Agent（面向整个任务）。

  • 五次跃迁：补全 → 对话 → Agent → 云执行 → Work Runtime。
  • 人不是兜底，而是 Runtime 里的决策节点：READ / DRAFT / WRITE / CRITICAL 四级动作分级；高风险动作显式分级授权留痕。
  • Work Agent 终点是 Outcome（产物 + 状态变化 + 证据），而非传统助手的 Output。

证据闭环与 WorkBuddy 三层闭环

  • 证据闭环：意图 → Spec → 执行 → 验证 → 证据 → 改进。「没有证据的自动化，只是更快地产生不确定性」。
  • WorkBuddy 三层闭环：CodeBuddy（智能编码）+ WorkBuddy（办公协同）+ Managed Agents（托管运行）。Harness 架构含：交互触发 / Agent 编排（Planner·Coordinator·Specialist）/ Context·Memory·Tools·Skills·Policy·Evaluation / 独立沙箱 / 治理观测。
  • 落地法 30 / 60 / 90 天：Value → Control → Reuse；附治理清单（身份 / 数据 / 工具 / 观测）与四类价值指标。

上下文与记忆（三层）

  • 云端 Profile：只读长期画像（职业、习惯、近期关注）
  • 用户级 MEMORY.md：写「记住」时落盘，跨项目硬规则（约 4000 字上限）
  • 空间当日日志：系统写，记录各空间发生了什么
  • 三层都管不到的 = 项目级经验（工作流底盘）

何时开新会话 —— 四个信号

  1. 开头定的规矩开始被忘（如「别动表头」又动了）
  2. 话题已换（旧上下文全是噪音）
  3. 同一段改了几轮越改越差（陷进局部最优）
  4. 反复重申同一要求（基本没救了）

→ 别喊「重做」（会毁掉已改对的部分）；要么指明位置局部改，要么带结论开新局。开新局前让它写 handoff.md（已定结论 / 待办 / 坑），新会话首句「先读 handoff.md」。

四条纪律（每条对应一次翻车）

  1. 改文件前先备份：文件名加日期，让它「复制一份再改」
  2. 改写 / 复盘 / 分析先上传素材：别让它凭空编
  3. 长对话定期自我摘要：每完成一大步发「用两三句话总结进展和待办，钉在这里」，成为高权重参考点
  4. 关键决策用 @ 钉住上下文：比反复强调管用得多

plan 模式


输入框左下角【计划】先出方案 → 确认再动手；提示词优化在右下角 ◇。

二、嘉宾分享

王炳宇《FDE 视角下：基于 WorkBuddy 的研发协作与落地实战》

九四智能 提示词工程部负责人；GDG / HDG 广州组织者。副标题：AI 不只是会聊天——Prompt、Context、Skill 与 Agent 的工程化实践。

  • 核心命题：AI 不该只当聊天框，而该接进真实工作流，成为把成品交付到文件夹的「工作台」——区别不在会不会问，而在有没有沉淀。
  • 关键要点
    1. 提示词工程化「不会写就先会抄」：专家广场搜「提示词工程」（40 位专家）让专家补结构化提示词；口诀「我的提示词是：」+ 大白话；「一键做同款·换皮不换骨」，骨架四块 = 目标 / 输入 / 约束 / 输出格式。五客户项目实测：一次生成可用率 35→82%、平均改轮 5.2→2.1、单任务耗时 22→9 分钟、lint 通过率 64→91%。
    2. 上下文与记忆「少即是多」：项目型任务建「空间」（硬盘真实文件夹）；三条纪律——Plan 出现「覆盖原文件」即刹车、别让它「补齐」缺失数据、局部修改要说「只改这里」。
    3. 全局指令：设置 → 个性化 →「给 WorkBuddy 的指令」全局生效（结构化 AI 工作顾问、最小必要改动原则、模式自动切换）。
    4. Skill = 写给 AI 的岗位 SOP：SKILL.md 含 name / description / 执行步骤 / 禁做事项；description 是「触发器」不是简介；触发漏斗四关（被触发 → 读得对 → 做得稳 → 可迭代）；调试做回归（症状 / 根因 / 修法）；直接拆别人（灵感频道一键做同款、GitHub 的 workbuddy-skills / WorkBuddy-Starter / WorkBuddyGuide）；与 MCP 分工：Skill 管「怎么做」、MCP 管「接外部」。
    5. 自动化与专家团：Ask / Plan / Craft 三句式；先手动跑通再挂定时，口令管理 + 两条红线；已跑案例：每日企业风险监控日报、按岗位定制 AI 工具箱、Skill 流、每周自进化。
  • 金句：「任何东西尽量留存本地——与 AI 协作的复利，来自不再从零开始。」

孟小鹏《从 AI Coding 到 AI Engineering：AI 时代开发者工作流的重构与实践》

资深 AI 应用开发工程师。

  • 核心命题：AI Coding 止于代码片段，Agent 走到验证通过；开发者正从「写代码的人」变成「设计 AI 工作流的人」。
  • 关键要点
    1. AI Coding 边界：典型路径 = 提出需求 → 生成实现 → 集成代码 → 人工收尾；「代码交付之后，验证与集成仍在工程侧」。
    2. Agent 定义：围绕目标持续执行直至验收通过。Agent = 一条执行循环：行动改变环境，结果决定下一步。
    3. 技术架构单步循环：Context → LLM → Tool Call → Observation → Context。Context 含目标 / Skills / Memory / RAG / Observation；Tool Call 经 MCP / Tools 执行文件、命令、接口、检索。
    4. WorkBuddy = Agent 运行时：循环 / 授权 / 工具协议 / 失败重试已内置，人负责目标与判断。三类能力入口：专家 / 专家团（人设 + 方法论 + 工具链）、Skill（可复用工具能力）、连接器（腾讯文档 / 会议 / 企业微信 / 飞书 / 钉钉 / TAPD / ima / 乐享 / 腾讯云 / 腾讯自选股 / QQ 邮箱等）。
    5. 实践案例：投研（研究 → 报告 + 可视化）、专利调研（检索 → 结构化笔记）；Life Energy——用 WorkBuddy 从 0 做的个人生活记录 App（睡眠 / 饮食 / 运动 → 生命力分数），AI 能力链：用户记录 → Memory → RAG → Agent → Tool → 建议。
    6. AI Engineering 定义：以 Agent 为核心，把 Skills / Memory / Knowledge / Tools 放进真实流程（分析 → 开发 → 测试 → 验证）。
  • 金句：「AI Coding 改变了我们写代码的方式。AI Engineering 正在改变我们做软件的方式。」

安轲《非研发背景的 AI Coding 实践》

腾讯 FDE 专家 / WorkBuddy·CodeBuddy 客户成功。副题：上手不难——把业务问题做成可用工具。

  • 核心命题：业务判断由人负责，重复步骤借助工具；非研发也能用 Vibe Coding 做出可用工具，并通过「嵌得进、验得了、转得动」沉淀为团队能力。
  • 关键要点
    1. 从最熟悉的小事开始：不写代码，先把需求、规则和验收讲清楚。起点案例：Workshop 方案生成器、售后工单分析。
    2. 案例一·拆分输入与规则：「变化的是输入，不变的是规则」——客户 / 人数 / 时段为输入项，排期 / 评分 / 模板为可复用规则；先跑通固定流程再扩展场景。
    3. 方法论·业务验证五步：①定标准 ②建样例（高频 + 边界 + 不适用 + 缺条件）③分层测（结果 / 证据 / 行为 / 稳定复现）④改判分离（业务定标准、改的人不判分）⑤持续回归。坑：触发正确 ≠ 结果正确；样例对真实数据就错；同人既改又判分；只改提示词补丁叠加；重试一次成功当修好。
    4. 三个方向：嵌得进（先进真实工作再谈自动化）、验得了（验收是需求一部分）、转得动（沉淀为资产才算能力）。
    5. 案例二·从个人 Skill 到团队资产：个人写 Skill 提效 → SkillHub（Skill / MCP / Agent 三类资产统一上架、标负责人与权限、同事复用）→ NexTAM 工作台（一个入口组合资产，关键动作人确认）→ 数字员工（组装 / 小范围灰度 / 人工兜底 / 评测回流）。
    6. 团队三点归纳：接入（MCP 接业务系统）、沉淀（平台 SkillHub）、运营（机制 + 负责人 + 评测集 + 灰度）。
  • 启示：业务把问题讲具体（真实场景 / 规则 / 验收样例 / 原型反馈），研发把工程做扎实（架构 / 质量 / 安全 / 发布维护），共同验收。

阮子豪《次时代桌宠》

华南理工大学。示例角色「格温 Gwen」——一只常驻桌面的 AI 伙伴。

  • 核心命题：与其再做一个用完即关的聊天框，不如做一只「常驻在场、会被记住」的桌宠——先有存在感，然后才可能被记住。
  • 关键要点
    1. 三件同时成立：会聊天（固定人格 / 语气、接住上下文）、会记事（基于 llm-wiki 知识库，写入 → 组织 → 召回，现以关键词检索为主、下一步接向量检索）、会变形态（桌面角落 + 全息仓同一内核，换身体不动人格）。
    2. Vibe Coding 三步：我做（用「我想要什么效果」说清目标）→ 它做（读代码 / 写代码 / 跑命令 / 看报错自改）→ 我做（打开实跑验收，不听「已完成」）。
    3. 三个踩过的坑：「已完成」≠ 事实（要验证结果 + 对照变更清单）；一次说太多会丢一半（拆成多任务并行、一任务一目标）；不写文档下一轮从零（写进 AGENTS.md 与 docs/）。
    4. 工程四层架构：交互层 / 会话层（人格提示词 + SQLite 上下文）/ 知识层（LLM-WIKI）/ 模型层（可切换 LLM API），层间只走接口。
  • 启示：把规矩、上下文、验收标准写进文件（AGENTS.md / docs/），让 Agent 每轮从沉淀起步——「把 AI 当同事用」。

欧阳洪鑫《让创造发生》

个人开发者 / AI 应用工程师（STARoy）。副标题：从 0 到 1，用 WorkBuddy 搭建一个 AI 应用。

  • 核心命题：想清楚再动手，让专家接力，把时间留给创意，让想法真正落地。
  • 关键要点
    1. 三个轻量应用对应三个需求：「到点」（记账与日常管理）、「死了么」（独居安全·签到与异常提醒）、「钱包请等等」（消费决策·把购买前的犹豫变成一次讨论）。
    2. 动手前 5 问：①需求多久做一次（频率低别做）②怎么判定成功（核心页面 / 仪表盘先定）③关卡从哪来、玩法多久变（决定模型调用 / 定时 / 成本）④什么算异常、阈值多少（告警降级边界）⑤结论给谁看、怎么送达（交付形态）。
    3. AI 开发六阶段：剧情与世界观 → 玩法与关卡 → 安全边界 → 批量生成 UI → 开发与迭代 → 部署上线；用 plan 模式先出方案再动手。
    4. 专家接力流水线：叙事工程师 → 游戏策划师 → UI 设计师 → 开发工程师 → 运维专家，串起《弥留之门》（number-door）从剧本到云端部署。
    5. 经验沉淀三件套：wa-gamexuqiu（模糊想法 → 可开工需求）、askmore（AI 反复追问确认需求被接住）、写代码的 Skill（Daliu-Awesome-Skills）。
  • 启示：把「需求澄清—方案—实现—部署」拆成可交接的小任务，经验以 Skill / 仓库形式沉淀复用。

甘皓玮《告别千篇一律的“AI 味”把 UI 范式沉淀为 Skill》

署名 / 搭档「黛琳」（多页落款「黛琳 & WorkBuddy 出品」）。

  • 核心命题：AI 时代不缺生成能力，缺的是你的审美有没有被「沉淀」下来——先沉淀，再生成。
  • 关键要点
    1. 「AI 味」三根源：模型学的是审美最大公约数（最安全最普通）；提示词穷举不了审美（长则啰嗦、短则跑偏）；对话框不记事（这次调好的风格下次归零重来）。
    2. 三步法：收集（投喂好 UI / 官网 / 海报，抽色值 · 构图 · 动效）→ 沉淀（Token + 图案 + 签名元素 + 动效纪律，写入 SKILL.md 与模板）→ 生成（加载 Skill，配色布局质感自动对齐）。
    3. Skill 四层结构：Token 层（色值 / 字号 / 间距 / 圆角，全部溯源变量）、图案层（布局套路 + 面积纪律，强调色 ≤10%）、元素层（地标剪影 / 纹理 / IP 等签名式记忆点）、校验层（红线 + Checklist 逐条自检）。
    4. 渐进式披露：SKILL.md 唯一必须；启动只加载 name + description（几十 Token，装 100 个不炸），触发才读完整 SKILL.md，执行按需读 references/、跑 scripts/。Prompt = 任务，Skill = 做法（Encoded Preference / 经验资产化可 Git 管理）。
    5. 实战产出：wuhan-hackathon-ui、nba-bordercast（近黑底 + 信号橙 ≤10%，clip-path 擦除 + KPI 滚动）、现场 workbuddy-salon-ui（深可可棕 #3A2214 · 荧光青绿 #2FF4CB · 企鹅 / 广州塔 / 早茶虾饺，5 红线 7 Checklist）。
  • 启示：把设计经验蒸馏成可积累、可共享、可迭代的范式 Skill——「同一个方法换一个场景就是一套新范式」，让每次生成站在上次成果之上。

共同点：所有人都把「与 AI 协作」当成可积累的资产——提示词、Skill、验收样例、知识库、审美范式，一旦沉淀就能复用、回归、迭代，复利来自「不再从零开始」。

四、可落地建议清单（整合自全场）

  • 提示词 / Spec：先抄后写；骨架 = 目标 / 输入 / 约束 / 输出格式；验收标准写进需求，不靠口头。
  • Skill：description 当触发器；触发漏斗四关（被触发→读得对→做得稳→可迭代）；先拆别人再自写；高频活才固化；格式规范 + 渐进式披露。
  • 记忆 / 上下文：项目建空间留档；三层记忆分工；关键决策 @ 钉住；长对话定期自我摘要；开新局写 handoff.md。
  • 自动化：先手动跑通再挂定时；Ask/Plan/Craft 分清边界；机械化苦工交给 AI，人留判断与决策。
  • 非研发落地：从最熟悉的小事起；输入与规则分离；业务验证五步 + 改判分离；先进真实工作再谈自动化。
  • 创造 / 产品：动手前 5 问；plan 模式先出方案；专家接力拆任务；经验以 Skill / 仓库沉淀。

附：开源经验沉淀

  • wa-gamexuqiu：模糊想法 → 能开工的需求
  • askmore：通过 AI 反复追问，明确需求是否被接住
  • 写代码的 Skill：拿需求一个闭环一个闭环做出来

主线一句话


Vibe → Spec → Harness（氛围感知 → 策略可执行透明）→ Coding Agent → Work Agent（能力从代码扩散到业务）→ Runtime → WorkBuddy（中台化场景与测度，明确落地）→ 洗牌 → 规模化（从工作流定位价值、建立战略)。
