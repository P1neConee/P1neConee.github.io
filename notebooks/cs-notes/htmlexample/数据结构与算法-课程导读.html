模块 2 · 线性结构

第2-5集
修仙比喻：四象：数组为基、链表为变、栈管后进、队列管先进。

核心知识点

  • 数组：连续内存、随机访问 O(1)，但插入删除要搬移 O(n)
  • 链表：非连续、靠指针串联，插入删除 O(1)，但查找 O(n)
  • 栈：只在尾部操作的 List，LIFO，用于函数调用栈、括号匹配、表达式求值
  • 队列：FIFO，用于广度优先遍历、任务排队、缓冲区

模块 3 · 哈希表

第6集
修仙比喻：瞬息符：以名为引，一念即达。

  • 哈希函数把键映射到数组下标，理想情况查找/插入 O(1)
  • 哈希冲突的两大解法：链地址法与开放寻址法
  • Java HashMap 与 Python dict 的底层都是哈希表——这是「为什么 dict 这么快」的答案

第7-8集

核心知识点

  • 树的基本概念：根、度、深度、高度、叶子、子树
  • 二叉树的代码实现（递归定义天然匹配树结构）
  • 前序/中序/后序/层序遍历——递归思想的第一课，也是后续所有树算法的基础

模块 5 · BST 与堆

第9-11集
修仙比喻：权衡：BST 以序换速，堆以极值为尊。

核心知识点

  • 二叉搜索树 BST：左<根<右，查找/插入平均 O(log n)
  • BST 的致命问题：有序插入会退化成链表，退化后 O(n)
  • 堆（大根堆/小根堆）：为取极值而生，插入删除 O(log n)，取极值 O(1)
  • 堆的经典应用：Top K 问题与优先队列（LeetCode 295）

模块 6 · 高级树结构

第12-17集
修仙比喻：演化：从压缩、补全、自平衡到多路，皆为对抗退化。

核心知识点

  • 字典树 Trie：前缀共享，自动补全与前缀匹配的核心
  • AVL 树：严格平衡的二叉搜索树，解决 BST 退化
  • 红黑树：适度平衡的艺术，用更少的旋转换更好的综合性能，Map 底层常见
  • B 树：多路平衡搜索树，为磁盘/大数据设计，降低树高减少 IO
  • B+ 树：B 树的变体，数据全在叶子且叶子相连，数据库索引的基石

  • 基础概念：顶点、边、度（入度/出度）、有向/无向、带权

模块 8 · 图算法

第21-25集
修仙比喻：运筹：最优连接、最短路径、先后次序、关键链路。

核心知识点

  • 最小生成树 MST：用最小代价连通所有点（Prim / Kruskal）
  • Dijkstra：单源最短路径，贪心 + 优先队列，边权不能为负

第2集 数组：内存世界的原住民 BV1utqHBNE5o 转写 好

核心知识点

  1. 数组定义：一块连续的内存空间，存放一组相同类型的数据；"连续存储 + 同类型（步长 size 一致）"是其高性能的根基。
  2. 随机访问 vs 顺序访问：随机访问=指哪儿打哪儿，给出下标即直接定位（O(1)）；顺序访问（链表）需从头数，O(n）。数组凭"连续+同 size"支持随机访问。
  3. 寻址公式：addr = base + i × size；CPU 只需一次乘法 + 一次加法即可算出任意元素地址。这是 O(1) 读取的硬件依据。
  4. 硬件加速：基于"局部性原理"，CPU 的 prefetch 会按 cache line（一般 64 字节，int 可预取 A0~A15）把附近数据预读到高速缓存，数组不仅算法层 O(1)，物理执行也远快于链表。
  5. 时间复杂度/大 O：衡量"操作步数随数据规模的增长趋势"而非绝对时间；简化三原则——只保留最高项、忽略常数系数、默认讨论最坏情况。常见级别：O(1) 常数级、O(n) 线性级、O(n²) 平方级（应尽量避免）、O(log n)。
  6. 数组的偏科：读 O(1)、写 O(1)；但在中间/头部插入、删除需搬移元素保持连续，复杂度 O(n)。仅末尾插入删除才是 O(1)。
  7. 动态数组：为解决固定长度痛点引入动态扩缩容——存满时申请 capacity×2 的新空间、复制旧数据（C++ 乘 2，Java 默认 ×1.5）；单次扩容代价高但均摊后 PUSH_BACK 仍为 O(1)；乘二是兼顾"内存浪费"与"扩容频率"的保守策略。

第3集 重要程度仅次于数组的数据结构——链表 BV1riq6B6E7V 转写 好

核心知识点

  1. 链表定义：由一组零散（不要求连续）的内存块组成，每个节点含"数据本身 + 指向下一节点地址的指针"；内存离散，可充分利用碎片空间（对比数组需一整段连续内存）。
  2. 生活类比：藏宝图——节点 = 奖励（数据）+ 下一处线索（next 指针），顺藤摸瓜找到末尾。
  3. 代码实现：结构体 `node { data; node* next; }`；`create_node` 用 malloc 申请单节点空间、next 置 NULL；理解结构体与指针是学懂链表的关键，也是后续哈希表/树/图的基础。
  4. 插入 O(1)：先 `new->next = B->next`（指向 C），再 `B->next = new`；无需搬移 B/C 之后的节点。两步改指针即完成。
  5. 删除 O(1)：`current->next = current->next->next`（跨过待删节点），再 free 释放；需先判断 next 非空。
  6. 链表的软肋：无下标直接访问，找第 k 个必须从头遍历 next 链，O(n)——这正是其牺牲随机访问换来的代价。
  7. 变体：双向链表（加 prev 指针，可前后遍历，代价是多耗一个指针内存）；循环链表（尾节点 next 指向 head，用于轮询调度/约瑟夫问题，遍历须防死循环）。
  8. 数组 vs 链表对比：内存结构（连续/cache 友好 vs 离散/指针连接）、访问（随机 O(1) vs 遍历 O(n)）、插入删除（搬移 O(n) vs 改指针 O(1)）、空间（紧凑 vs 多指针但能吃碎片）；选型——读多改少用数组，增删多读少用链表。两者互补，是栈/队列的实现基础。

第4集 栈：只在尾部操作的 List BV1q9BEBkEbU 转写 好

核心知识点

  1. 栈定义：操作受限的线性表，只允许在同一端（栈顶）进行插入和删除；LIFO（后进先出）。生活类比：一摞盘子只能从顶部放/取。
  2. 核心操作均为 O(1)：push（入栈，放到栈顶）、pop（出栈，返回并移除栈顶）、peek（只看栈顶不删除）、is_empty、size；约定空栈 top=-1（数组实现时 top 是索引，size=top+1）。
  3. 实现选型：日常多用数组实现——省空间、cache 友好、无需申请/释放节点；因只在栈顶操作，数组的插入删除也是 O(1)；定长问题用动态数组，均摊后仍为 O(1)。链表实现较少用（额外节点开销）。
  4. 应用一·括号匹配：左括号入栈；遇右括号则 pop 栈顶比对是否匹配；扫描完栈必须为空（左括号多出或右括号多余均不匹配）。
  5. 应用二·表达式求值（两步都用到栈）：①中缀转后缀（逆波兰）——用"符号栈"调整顺序，规则：数字直接输出；左括号入栈；右括号连续弹出至左括号（左括号丢弃不输出）；遇运算符则只要栈顶运算符优先级≥自己就不断弹出，再入栈；最后清空栈。②后缀求值——用"操作数栈"：遇数字入栈，遇运算符弹两个数计算（先弹出者作 B、后弹出者作 A，执行 A-B / A/B，顺序错则结果错），结果入栈，栈顶即为答案。
  6. 其他应用：DFS / 回溯（最深处先处理、逐层回退）、函数嵌套调用（栈帧）、浏览器前进后退、撤销操作（Ctrl+Z）；栈可理解为"历史记录的管理者"。

第5集 队列：四大线性数据结构的最后一环 BV15QvzB9EGy 转写 好

核心知识点

  1. 队列定义：双端操作（队尾入队、队头出队）的受限线性表，FIFO（先进先出）；类比食堂打饭/地铁安检，体现公平。操作 push/出队/peek/is_empty/size 均为 O(1)。
  2. 实现选型：直觉上双端删除该用链表，但实际多数用数组（cache 友好、读取快）。纯数组出队需搬移 O(n)，故引入"循环数组"。
  3. 循环数组（环形缓冲）：物理仍是连续数组，逻辑首尾相接；用 front（队头有效元素下标）、rear（下一个待插入空位下标）、capacity 三量描述；移动统一用取模 (rear+1)%capacity；出队只改 front 指针、不搬数据（逻辑删除、物理保留待覆盖）。
  4. 空/满歧义与留空法：front==rear 既可能空也可能满 → 牺牲一个空间（容量为 N 最多存 N-1 个）：满条件 (rear+1)%capacity==front，空条件 front==rear。留空法利于并发（避免锁住头尾）。

第12集 哈夫曼树：如何实现高效数据压缩 BV1Tmr1BVEA3 转写 好

  3. 哈夫曼编码：左路径标 0、右标 1，根到叶子路径上的 0/1 序列即编码；所有字符都在叶子节点，具备"前缀特性"（无任何编码是另一编码的前缀）→ 解码无歧义、无需分隔符。

第17集 B+树：数据库索引基石 BV1JFzCBSENY 转写 中

核心知识点

  1. 定位：对 B 树的拓展，工程上最常用——数据库索引基石。
  2. B 树痛点：①索引密度低（内部节点既存 K 又存 data，能存的 K 少，树高不够极致）；②范围查询慢（数据散布，需逐次中序回溯）。
  3. B+ 树优化：①非叶子节点只存 K（索引/路标），不存 data；所有 K+data 都在叶子节点 → 节点变小、每磁盘页载更多节点、树更矮；②所有叶子节点用链表（指针）串起来 → 高效范围查询/顺序全表扫描。
  4. 规则（M 阶）：内部节点分叉最多 M、最少 ⌈M/2⌉；内部节点 K 数 = 分叉数-1；叶子节点 K 最少 ⌈M/2⌉-1、最多 M-1。
  5. 与 B 树异同：同——多路平衡、所有叶子同层、节点有序、插入删除需维持特性；异——B+树非叶子只存 K（瘦身）、数据绝对在叶子；B 树 K 全树唯一，B+树 K 会重复（父节点只是路标、叶子也有）；B 树节点间只连 parent，B+树叶子间有链表。
  6. 查找：从根二分下到叶子；即使内部找到 K 也要继续下到叶子取真实 data（路径稳定，不会忽快忽慢）。范围查询：定位起点后沿叶子链表顺序走直到超界，免回溯。
  7. 插入/删除：总在叶子插入（满了分裂，中间 K 复制到父节点，非上移）；删除可能下溢出，向兄弟借或合并，需维护叶子链表；比 B 树简单（数据只在叶子）。
  8. 优势：更矮、索引分离、查询稳定、范围查询快、对磁盘友好；应用于关系型/非关系型数据库（含 MongoDB）、文件系统。

第21集 最小生成树 (MST) BV1qrzXBkEmD 转写 好

核心知识点

  1. 最小生成树定义：①生成树=含所有 V 个顶点、恰 V-1 条边、无环、连通；②最小=边权之和最小。应用：N 城市铺电缆连通且总成本最低。图论中"连通且无环"即树。
  2. Prim 算法（逐顶点加，贪心）：从任意顶点出发，每次把"离当前生成树集合最近"的顶点拉入伙；维护 lowcast 数组（各顶点到树的最小距离）和 parent 数组；更新新顶点邻居距离→再找最小→循环 V-1 次。适合稠密图（复杂度与边无关、只看顶点数，朴素 O(V²)）。
  3. Kruskal 算法（逐边加，贪心）：所有边按权重升序排序，依次加边；加前用并查集（find parent）判环——两顶点根不同则可加、相同则丢；直至加入 V-1 条边或所有顶点连通。适合稀疏图（与边相关，O(E log E) 排序主导）。
  4. 并查集：每顶点初始 parent=自己（自己为根/leader）；加边时找两顶点根，不同则合并（一集合根设成另一集合根），相同则成环丢弃；可路径压缩优化查询。
  5. 对比：两者都是贪心；Prim 逐顶点（适合稠密），Kruskal 逐边（适合稀疏）；最小生成树权值唯一但形态可能多种。

  2. 事件时间：VE（顶点最早发生）= 前驱活动都完成的最早时刻，正向拓扑序 + 取 max；VL（顶点最晚发生）= 不耽误工期的最晚时刻，逆向拓扑序 + 取 min；起点与终点 VE==VL。
  3. 活动时间：E（边最早开始）= 该边起点 VE；L（边最晚开始）= 该边终点 VL − 边权；机动时间（buffer）= L − E。
  4. 关键活动 / 关键路径：机动时间为 0 的活动即关键活动；关键活动首尾相连组成的路径即关键路径。本例关键活动 A3、A5、A7，跨度 8 = 整体工期；关键活动"一分钟都马虎不得"，任一延期必拖整体。

6. 读后自测 8 题

Q1. 数组和链表的核心差异是什么？分别适合什么场景？
答：数组内存连续、支持随机访问 O(1)，但插入/删除需要搬移元素 O(n)，适合「读多写少、频繁按下标访问」；链表靠指针串联、插入/删除 O(1)（已知前驱），但查找必须遍历 O(n)，适合「频繁增删、很少随机查」。
Q2. 为什么哈希表的查找是 O(1)？什么情况下会退化？
答：哈希函数把键直接映射成数组下标，一步定位，所以均摊 O(1)。但当大量键发生哈希冲突时，链地址法会退化成链表（极端可到 O(n)）；恶意构造碰撞还能发起拒绝服务攻击。
Q3. BST 在什么情况下退化为 O(n)？AVL 和红黑树各自怎么应对？
答：按有序序列插入时，BST 每一步都只往一侧长，最终变成一条链表，查找退化到 O(n)。AVL 用严格平衡（任意节点左右子树高度差≤1）+ 旋转维持 O(log n)，但旋转频繁、写操作代价高；红黑树放宽为「适度平衡」（最长路径不超过最短的 2 倍），用更少旋转换取更好的综合写入性能。
Q4. Top K 问题为什么用堆比排序更好？复杂度差多少？
答：先整体排序再取前 K 是 O(n log n)；维护一个大小为 K 的小根堆，遍历时只在比堆顶大时替换，复杂度 O(n log K)。当 n 很大、K 很小时差距是数量级的，且内存只需存 K 个元素。
Q5. B 树和 B+ 树的关键区别是什么？为什么数据库索引偏爱 B+ 树？
答：B 树的每个节点都存数据；B+ 树的数据只存在叶子节点，且叶子节点之间用链表相连。这使得 B+ 树的单次查询更稳定（都要走到叶子）、内部节点能装更多键（树更矮、IO 更少），并且范围查询只需沿叶子链表扫描，非常适合数据库的区间检索。
Q6. 邻接矩阵和邻接表怎么选？
答：稠密图（边数接近 V²）用邻接矩阵，判两点是否相邻 O(1) 且实现简单；稀疏图（边远少于 V²）用邻接表，空间 O(V+E) 而非 O(V²)，遍历邻居也更快。现实中的社交网络、网页链接几乎都是稀疏图，所以用邻接表。
Q7. Dijkstra 和 Floyd 分别解决什么问题？能互换吗？
答：Dijkstra 解决单源最短路径（一个起点到所有点），贪心 + 优先队列，要求边权非负，复杂度约 O(E log V)；Floyd 解决多源最短路径（任意两点之间），动态规划三重循环 O(V³)。只在「起点固定」时用 Dijkstra；需要所有点对距离才用 Floyd。
Q8. 拓扑排序能用来做什么？它如何判断有环？
答：拓扑排序给出满足所有依赖的先后执行顺序，用于任务调度、编译依赖、课程安排。做法是反复取出入度为 0 的节点；如果最终输出的节点数少于总节点数，说明剩下的节点互相依赖，即图中存在环。
