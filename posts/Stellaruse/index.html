前言：这本手册该怎么读

这本手册是给谁看的

如果您是第一次接触 Hexo 或 Stellar，对命令行感到陌生，对”Front Matter”、”Collection”、”Widget”这些词一头雾水——那这本手册就是为您写的。它把官方技术文档翻译成了人话，并补充了大量”为什么要这样做”的解释。

这本手册和官方文档的关系

官方文档 本手册
定位 技术参考辞典 从零到一的教程 + 辞典
适合谁 已经熟悉 Stellar 的人 新手 + 需要快速查阅的人
内容 完整但零散 完整 + 按场景组织 + 步骤化
更新 跟随最新版本 基于本站 v2.0.0-alpha.1

本手册的目标：覆盖官方文档 100% 的配置项和功能点，但用更易懂的语言重新表述，并按照”第一次做某件事”的场景来组织章节。您既可以按顺序通读，也可以在遇到具体问题时直接跳到对应章节。

2.2 核心规则（记住这三条就够了）

规则一：文件放在哪决定了它是什么

文件位置 内容类型 示例
source/_posts/*.md 博客文章或专栏文章 日常记录、系列教程

规则二：文件名就是网址的一部分

文件位置 文件名 访问地址
source/_posts/my-post.md my-post /posts/my-post/
source/wiki/handbook/index.md index /wiki/handbook/index/
source/notebooks/reading/note-1.md note-1 /notebooks/reading/note-1/

⚠️ 极其重要：发布后不要再改文件名。一旦网站上线、有了访问量，改名会让旧链接失效，导致读者打不开页面。如果必须改名，需要在旧地址做重定向。

规则三：source/ 之外的文件都不会被发布

所以 文章模板/ 文件夹里的模板文件可以放心放，它们不会出现在您的网站上。同样的，根目录下的 使用与配置手册.md 也不会被发布。

3.1 _config.yml —— 站点基本设置（Hexo 基础配置）

这是 Hexo 的基础配置文件，控制网站的”身份信息”和基础行为。带 ★ 的是您最常改的。

3.2 _config.stellar.yml —— 主题配置（完整注释版）

这是 Stellar 主题的配置文件，控制网站长什么样、导航栏有什么、侧栏显示什么、哪些功能开启。带 ★ 的是您最常改的。

主题的默认值位于 node_modules/hexo-theme-stellar/_config.yml，本站的 _config.stellar.yml 只写需要覆盖的项。也就是说，您在 _config.stellar.yml 里没写的配置项，会使用主题的默认值。

3.2.1 顶层分区一览

在开始逐项讲解前，先了解 _config.stellar.yml 的整体结构：

分区 管什么
topbar 顶部导航栏：是否显示、品牌标识、菜单项、Widget
leftbar 左侧边栏：品牌信息、主菜单
rightbar 右侧边栏（配置方式同 leftbar）
footer 页脚：底部链接分栏、版权信息
profiles 不同页面类型的专属配置：菜单高亮、左右栏 Widget
article 文章展示：列表摘要长度、标签显示、阅读时间、相关文章
notebook 笔记本：列表排序、标签图标

appearance 外观：预设风格、配色、字体、圆角、背景
search 站内搜索：local / algolia

features 功能开关：深浅色切换、懒加载、灯箱、公式、图表

3.2.2 顶部导航栏（topbar）

关于 widgets 的说明：

  • 顶栏的 widgets 会从左到右依次渲染
  • menu 是特殊 Widget，它会把 topbar.menu 数组渲染成顶栏菜单
  • spacer 只存在于顶栏，作用是占据剩余空间，把后面的 Widget 推到右侧
  • settings 显示一个齿轮图标，点击后弹出外观设置面板（深浅色切换、字体等）

如果要新增顶栏菜单项：必须把现有菜单项全部写出来，再加上新的。因为数组是整体替换。

3.2.3 左侧边栏（leftbar）

每个菜单项的字段含义：

字段 含义 示例
id 菜单唯一标识（kebab-case），用于和active_menu 配对 post、wiki
title 菜单显示文字 近期发布
icon 菜单图标（default:图标名 使用主题内置图标） default:documents
url 点击跳转的地址 /、/wiki/
accent 菜单项左侧的强调色 '#1BCDFC'
type 特殊类型（如search） search

菜单项 id 的作用：

  • 用于 profiles 中的 active_menu 配对——当用户访问某个页面时，对应的菜单项会高亮
  • 例如访问首页时，active_menu: post 会让 id 为 post 的菜单项高亮

如果不想显示某个菜单项：直接删除该行即可。注意数组是整体替换，所以删除后也不会从别处冒出来。

3.2.4 页脚（footer）

每个 section 是一列，items 是列中的链接列表。可以增删改任意列和链接。

3.2.5 页面类型配置（profiles）

这是 Stellar 最灵活的配置之一——不同页面类型可以有不同的布局和菜单高亮。

覆盖语义：

  • 省略某个配置项 = 继承主题默认值
  • widgets: [] = 该区域不显示任何 Widget（清空）
  • widgets: [a, b] = 只显示 a 和 b（整体替换）

注意：Wiki 内容页默认隐藏固定菜单（只留目录树），所以不要在 profiles.wiki 上设置指向隐藏菜单的 active_menu，否则会报错。

第四章 Front Matter 完整参考

4.1 什么是 Front Matter

每篇 Markdown 文件最顶部的 --- 包围起来的部分，就是 Front Matter。它用 YAML 格式写，告诉系统这篇文章的标题、日期、分类、标签、归属等信息。

⚠️ 语法警告：Stellar 主题会对 Front Matter 字段做严格校验，写错字段或格式错误会导致构建报错。Doctor 命令会明确指出错误来源和修复方向。

4.2 字段完整速查表

字段 适用内容 类型 说明
title 全部 字符串 显示标题（不是网址，网址由文件名决定）
date 全部 YYYY-MM-DD HH:mm 发布日期
updated 全部 YYYY-MM-DD HH:mm 更新日期（可选，不写则沿用 date）
description 全部 字符串 摘要，用于列表卡片和 SEO meta
categories 博客文章 字符串列表 分类（建议用稳定的领域名：方法/工具/学习/思考/观察）
tags 全部 字符串列表 标签（笔记中可用/ 表示层级，如 阅读/方法）
cover 文章/笔记/集合 URL 字符串 列表卡片封面图，如/assets/cover.webp
permalink Wiki 页面 字符串 显式访问地址，必须与目录树中的 key 一致
collection 专栏文章/笔记本笔记 对象 声明归属：profile: topic/notebook + id: xxx
listing.priority 文章/专栏文章/笔记 非负整数 置顶，数字越大越靠前
excerpt 或 <!-- more --> 全部 字符串/注释 控制列表摘要，更推荐用description

第八章 标签插件速查大全

8.1 什么是标签插件

标签插件是 Stellar 提供的 Markdown 扩展语法，让您能在文章里插入各种样式丰富的内容块，比如提示框、折叠面板、标签、时间线、图库等。

基本语法：

  • 参数用空格分隔
  • 键:值 形式的是命名参数
  • 最后的文本参数会吸收剩余所有内容
  • 多行内容用成对标签：{% 插件名 %}…{% end插件名 %}

8.2 全部标签插件速查表

8.6 标签插件使用原则

  1. 适度使用：标签插件是为了增强内容可读性，不是为了炫技。每篇文章使用 3-5 个不同类型足矣。
  2. 颜色统一：同一种类型的信息尽量使用同一种颜色（比如所有提示都用 cyan，所有警告都用 red）。
  3. 移动端兼容：避免嵌套过深（比如 folding 里再套 tabs），在手机上可能显示不全。
  4. 先测试后铺开：不确定某个标签插件是否可用时，先在本地写一篇测试文章，跑 npm run doctor 确认无报错。
